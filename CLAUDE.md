# orsonbrooker.com

Orson's website: his pixel-art basketball game **Shootaround**, a player builder, an ideas board and a
private admin page. Orson is a kid; his dad (Luke) builds it with him. Players are Orson's friends, so
everything is written for kids and stays safe for them. More background: `README.md`.

**Docs:** `docs/architecture.md` is the living description of how it all works: the pieces, the domain
model and the main flows, with mermaid diagrams. It's committed; when a change alters something it
describes, update it in the same commit. Plans, proposals and other short-lived notes go in `notes/`
(gitignored, kept in the main checkout, so a worktree won't have it). `notes/growth-plan.md` is the current
plan for growing the game and the iOS app; read it when working on structure.

## How it's built

- **Site:** plain JavaScript modules (no framework), built with Vite. On every push to `main`, GitHub
  Actions (`.github/workflows/pages.yml`) runs `npm run build` and publishes `dist/` to GitHub Pages at
  orsonbrooker.com, behind Cloudflare. Pages: `/` (`index.html`, `home/`), `/games/shootaround/` (uses
  `<base href="/">`, so the game's code and assets live at the repo root), `/players/` (builder), `/ideas/`,
  `404.html`, `/lab/` (hidden effects test page).
- **Build:** `vite.config.js` bundles each page's scripts and stylesheets into `dist/build/` with hashed
  names (so new code always reaches visitors), and copies files the code fetches by URL (`assets/`,
  `icons/`, manifests, `CNAME`) unchanged. A new page goes in its `PAGES`; a new file fetched by URL at
  runtime goes in `STATIC` unless it's under `assets/` or `icons/`. New JS modules need nothing special:
  import them normally. The build stamps the commit into the game as the version it sends with scores.
- **Game:** `game.js` (the entry point that wires it up), `engine/` (court and projection, physics, loop,
  input, drawing helpers), `play/` (the shared state, shooting and the update, reactions, drawing the court,
  players, switching courts), `modes/` (one file per mode, same shape), `content/` (courts, player
  attributes, looks, spots, calls), `screens/` (menus,
  help, leaderboard, game over), `leaderboard.js`, `audio.js`,
  `phrases.js` (announcer lines), `fx.js` + `effects/` + `vendor/pixelfx/` (pixel effects), `shared/rules.js`
  (scoring rules, shared with the Worker), `daily.js` (daily challenge), `players/recolor.js` (builder players' colours).
  Canvas 2D, isometric court image, ball physics in metres with a fixed step.
- **Server:** `worker/` is one Cloudflare Worker on `orsonbrooker.com/api/*` and `/admin*`, with a D1
  database. Code is in `worker/src/`, split by area (`index.ts` is the router; `ideas.ts`, `players.ts`,
  `scores.ts`, `admin.ts`, `access.ts`, `cache.ts`, `notify.ts`, `stats.ts`, `util.ts`), the admin page is `worker/src/admin.html`, schema changes are
  `worker/migrations/NNNN_*.sql`. Cloudflare Access guards `/admin` (and the Worker checks its token).
  Bot checks use Turnstile; IPs and device ids are stored only as keyed hashes.
- **Art and sound** are generated by `tools/` (see README): `build_character.py` and `build_regions.py`
  (players), `build_voice.py` (announcer), `build_favicons.py`, `build_share_images.py`,
  `build_game_cards.py`, `build_sfx.py` (recorded effects), `pixelart/video_body.py` (Orson, from generated
  green-screen videos listed in `art/video/orson.json`; the videos live outside the repo). Big source files
  and caches (`.character-cache/`, `.voice-cache/`) are gitignored.

## Rules

- **Nothing goes live without Luke saying so** ("go live", "push it", "deploy"). That covers pushing
  to `main`, deploying the Worker, and any write to the live database (including data fixes and
  marking ideas done). Build and test locally first, then ask. Approval is for that change only.
- **Deploy only committed code.** `cf deploy` builds whatever is on disk; never deploy (or loop a retry
  of a deploy) from a working tree with unfinished changes.
- **Stay on Cloudflare's free tier.** Use the `cf` CLI (there's no Wrangler config).
- **Other sessions share this checkout.** Work in a worktree; stage only your own files; never use a
  bare `git stash`. Before pushing, `git fetch` and rebase if `main` moved.
- **Secrets** live only in `worker/.secrets.json` and `worker/.dev.vars` in the main checkout. Never
  commit them; the repo is public.
- **Kids:** friendly words ("Let's keep it friendly. Try different words."), nicknames not real names,
  the rude-word filter on anything typed, no third-party tracking. Don't explain behind-the-scenes rules
  in the app (e.g. that the leaderboard keeps one row per player per device).
- **Look and feel:** pixel art and the pixel font for short game text, normal text for anything longer.
  Pixel icons (`ui/icons.js`), never emoji. Styled dialogs (`ui/confirm.js`), never `alert`/`confirm`.
  Phone first: no sideways scroll, use the height, big enough tap targets. Respect reduced motion.
- **Leaderboard features:** anything new that scores or shows on a player's card must only count for
  games played after it went live: add it to `FEATURE_FROM` in `worker/src/scores.ts`. Work out derived
  numbers from the saved score, never by re-scoring old shot logs with today's rules.
- **Scoring rules live once, in `shared/rules.js`:** fire levels and bonuses, bonus balls, points, modes,
  recounting a shot log. The game imports it in the browser and the Worker imports it to check scores, so
  never copy a rule into either side. The server's checks on a sent game are in `worker/src/scoring.ts`.
  Run `npm --prefix worker test` after changing either (Node's test runner, no extra installs).
- **Courts and player attributes are data:** a court (art, geometry, 3-point line, gravity, wind) is an
  entry in `content/courts.js`; what a player is good at is `content/attributes.js`. Every player is neutral
  until Luke and Orson set values there, since the leaderboard compares everyone.
- **Be lenient on cheating:** reject only the impossible; flag the odd ones for the admin and keep them
  on the board.

## Security (the repo is public)

Assume anyone can read every line and the whole history. A review on 6 Nov 2026 found no secrets in the
code or history, and no XSS or SQL injection; keep it that way:
- User-typed text (nicknames, ideas, player and team names, credits) only ever reaches the page through
  `textContent`; `innerHTML` only with constant strings or `icon()`. Every value in SQL is bound.
- Fine to be public: the D1 database id, the Turnstile site key, the Access team domain and AUD.
- Every cheap-to-call write needs a per-IP limit (and Turnstile where a kid types something); public reads
  go through the Worker's short cache so a request loop can't use up the free tier's daily D1 quota.
- Admin: Cloudflare Access plus the Worker's own token check; admin POSTs must be same-origin JSON. The
  local `DEV_ADMIN` bypass only works for requests to localhost.
- Kids' privacy: public responses show dates, never exact times; nicknames, not real names; no third-party
  trackers.
- `tools/dev/lan_server.py` (phone testing, reachable by anyone on the Wi-Fi) never serves hidden files or
  `worker/`, `notes/`, `tools/`, `art/`. Don't serve the main checkout's root with any other server on
  `0.0.0.0`: `worker/.secrets.json` holds the production secrets.
- GitHub Actions are pinned to exact commits; Dependabot opens weekly update PRs (`.github/dependabot.yml`).
  Pin new packages to exact versions.

## Running it locally

From a worktree, set up once:

```sh
npm ci                                                # the site's build tools (Vite)
npm --prefix worker ci
cp ../../../worker/.dev.vars worker/                  # from the main checkout
cp -R ../../../worker/.cloudflare/types worker/.cloudflare/  # generated types, else tsc fails
(cd worker && npx cf d1 migrations apply 67713a08-4e9f-46b0-874f-bbf9ccf05c4c --local --persist-to .cloudflare/state)
python3 tools/dev/copy_live_db.py                     # optional: real ideas, players and scores, locally
```

- **Worker:** `cd worker && npx vite --port 8787 --strictPort` (`cf dev` can't take a port). It must run from `worker/`: `npx vite` at the repo root is the site's build, and answers every URL with a page. Add `--host`
  to reach it from a phone. It listens on IPv6 (`localhost`, not `127.0.0.1`). `/admin` needs no sign-in
  locally, and only opens on this Mac (not from the phone or the network with `--host`).
- **Site:** `npm run dev -- --port 5173 --strictPort` (Vite's dev server, from the repo root) while working,
  then before going live `npm run build` and serve what will be deployed:
  `python3 -m http.server 5175 --bind 127.0.0.1 --directory dist`. The game uses the local Worker when on
  localhost. Other sessions may already hold these ports: check with `lsof -i :PORT` and pick a free one.
- **Phone or iPad:** `npm run build`, then `python3 tools/dev/lan_server.py 5174 dist` and open
  `http://<Mac IP>:5174/games/shootaround/` (`ipconfig getifaddr en0`).
- **iOS app** (Capacitor, `ios/`, `capacitor.config.json`): `npm run build:app` (the site plus
  `tools/app/prepare.mjs`, making `dist-app/`, which opens on the game), then `npx cap sync ios`, then build
  in Xcode (`npx cap open ios`) or `xcodebuild` for a simulator. In the app, pages come from
  `capacitor://localhost` and talk to the live API (`api.js`); the Worker allows that origin. Haptics are
  `haptics.js`. The robot check (Turnstile) inside the app is untested: sending a score or a player from
  the app may need App Attest instead.
- **Test mode:** add `?debug` to the game URL: shows the rim and lines, exposes `window.game`, and scores
  can't be sent. `await window.game.setCourt("gym-low-gravity")` (or `"gym-windy"`) tries a test court
  from `content/courts.js`.
- **Automated play:** `node tools/dev/play.mjs` plays every mode in a headless Chrome and sends the scores to
  the local Worker (instructions at its top). Use your own headless Chrome as it describes: the app's browser
  pane pauses the game when hidden, and the shared puppeteer browser gets navigated by other sessions. It
  drives real input (Space keydown/keyup on `window`, letting go when `player.anim === "jump" && player.t >= 0.29`).
  In `?debug`, `window.game.setSeed(...)` makes a game repeatable: the same seed and input give the same game.
- **Page check:** `node tools/dev/check_pages.mjs 9333 http://localhost:5175` opens every page of the built
  site in the same headless Chrome and lists script errors and failed loads.
- **Type-check the Worker:** `cd worker && npx tsc --noEmit -p .` (needs `worker/.cloudflare/types`; it
  checks `shared/` too).
- **Tests:** `npm --prefix worker test` runs `worker/test/*.test.ts` (scoring rules and score checks).
- **Local database:** `npx cf d1 raw <id> --local --persist-to .cloudflare/state --sql "..."` (`d1 query`
  has no local mode; very long SQL must be split up).

## Going live

Use the `go-live` skill. In short, in this order: live database migration, then `cf deploy` (only if the
Worker changed), then push `main`, wait for the Pages workflow to build and deploy that commit
(`sh tools/dev/wait_pages.sh <sha>`), then check the live pages and API. Then tell Luke to `git pull` in the
main checkout.

## Gotchas

- **Caching.** Cloudflare caches for 4 hours. Scripts and stylesheets have hashed names, so they're never
  stale, but the pages themselves and files under `assets/` keep their names: if a page looks old right
  after a deploy, purge it: `npx cf cache purge -z orsonbrooker.com --force --body '{"files":["<url>"]}'`
  (run from `worker/`). Check live only after `wait_pages.sh` says the deploy succeeded. Cloudflare blocks
  Python's default user agent; use `curl`.
- **The old `?v=` stamps are gone** (and `tools/stamp_versions.py` and the pre-commit hook with them). The
  `?v=` left on icons, in manifests and on sprite URLs in `assets/characters/index.json` are those files'
  own cache versions: keep them.
- **Worktrees:** a new worktree has no `node_modules`, `.dev.vars`, generated types, `.character-cache/` or
  `.voice-cache/`; copy what you need from the main checkout, and copy new voice clips back
  (`rsync -a .voice-cache/ <main>/.voice-cache/`). The worktree guard refuses compound shell commands,
  computed `cd`, `$(...)` in commands and chained git: run plain separate commands, or put the logic in a
  script in the scratchpad.
- **Cloudflare API outages** ("no healthy upstream") happen: retry later from the committed tree, don't
  leave a retry loop running over a changing working tree.
- **Player sprite sheets** are drawn by Luke from `art/character-template.png` (16:9, 7x2 poses) and built
  with `tools/build_character.py`. The cut-out keeps backdrop-coloured patches inside the body unless
  they're the backdrop colour itself; check rebuilt bodies recoloured on a green background so wrongly
  filled gaps and see-through holes both show. Orson's sheets are built from video with
  `tools/pixelart/video_body.py art/video/orson.json` (needs Luke's videos); after rebuilding, run
  `tools/dev/check_prints.mjs` on `?pixel` and restamp his `?v=` in `assets/characters/index.json`.
  `?old` plays his earlier art.
- **Layered players** (builder bodies on Orson's moving body, `players/layered.js`): a new head is
  `art/heads/head-<style>.png` (16:9, two rows of five views; brief in `art/heads/README.md`), built with
  `python tools/pixelart/heads.py <style>` (check `art/heads/preview-<style>.png`), tried with
  `?debug&head=<style>`. Naming it after a builder body id replaces that body for every player who chose it.
  After rebuilding Orson's video sheets, run `tools/pixelart/rig.py` then `heads.py` (all heads) again.
- **Kids from video** (the builder's Curly and Buns, `art/video/<kid>.json`): rebuild in this order,
  `video_body.py`, then `tidy_regions.py`, `key_hair.py` and `ball_key.py` on `<kid>-detail` (those two need
  Flow's magenta hair and ball repaints of the kid's frame grids), then `check_regions.py <dir> <out.png> --fix`
  and again without `--fix`: it must say 0 frames with issues, and its contact sheet (every frame in clashing
  colours) must show nothing changing with the wrong part. Last, `video_bases.py curly buns` points the
  builder's bodies at the new sheets (`?v=` stamps, card picture from `recover-fl` frame 6, thumbs); if frame
  picks move that frame, check the cards. Videos and Flow references get names
  unique to the kid (Flow's project already holds older `grid-NN.jpg` files), and every downloaded repaint is
  matched to its grid by picture before it's used. Make kids' videos with mid-brown hair, so any colour
  recolours well.
- **Picker order** comes from `assets/characters/index.json` (Orson first); rebuilding a
  character can move it, so check.
- **Ideas board data:** the `apps` table holds categories (`basketball` = Shootaround, `new-game`,
  `website`). `done_at` is set when an idea is first marked done; the Done column sorts by it.

## Product notes

- Shootaround modes: Time attack (60s), Sudden death (first miss ends it; gets harder: the green shrinks
  and, from 5 in a row, moves), Around the World (7 spots, fastest time; the green moves a little), the
  3-point contest (5 racks of 5 threes in 60s, the last ball of each a money ball; the green moves), which
  stays hidden outside `?debug` until Luke's rack art is in (`art/three-point-contest.md`), and HORSE (2-4
  players pass one device; match the leader's shot, from the same spot with the same moving green, or get
  a letter; no leaderboard, a finished match earns flat coins). The
  scored ones each have their own leaderboard (This week / All time, one row per player per
  device, or per set of devices joined with a pairing code). Fire at 3 in a row (+1), purple at 6 (+2), blue supernova at 10 (+3); money and rainbow balls;
  a daily challenge kept on the device. After any game, Replay plays its best shot again in slow motion
  (re-flown from what was recorded at the release, not recorded frames; see `play/replay.js`).
- Leaderboard rows (except your own) have a small flag to report an unfriendly name (Apple asks for this
  where kids type names). Reports wait in the admin inbox until the name is renamed, hidden or marked
  "Looks fine".
- The flow: tap or Space to play, choose a game, choose a player.
- Players: Orson (built in), and kids' own players from the builder (10 bodies, recoloured from region maps);
  requests wait in the admin inbox. A player is a he or a she (from the body: ponytail and buns are she, for now; the admin can override);
  the announcer says "She's heating up!" for a she, and skips lines about he or she when it isn't set. A new
  announcer line that says he, his or him needs its she version in `SHE` in `phrases.js` (the tests check). Only add real kids as players if Orson knows them and their family is OK
  with it.
- The ideas board is how Orson's friends steer the game; votes matter. Top requests: Moni as a player,
  1v1/2v2/3v3 online, a city to explore, gear and unlocks, new courts.
